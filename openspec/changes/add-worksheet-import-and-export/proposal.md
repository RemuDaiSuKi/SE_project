# Proposal

## Why

老師目前讓各組拿填空式學習單（Guided Notes，存在 Google Sheets）上台寫黑板搶答，耗時又難以統計。課堂搶答系統要把這個流程搬到線上，而所有後續功能（搶答活動、結果檢視、寫回）都建立在「系統能正確讀懂任何一份學習單的結構」之上，所以必須先完成學習單的匯入與確認，以及結果的輸出管道。

本 change 是兩個 change 中的第一個，必須與 SpecKit 小組實作的同一系統功能一致；第二個 change `add-live-buzzer-activity` 會在此基礎上加入線上分組搶答。

## What Changes

- 新增老師登入：密碼只來自環境變數，未設定時伺服器拒絕啟動；每個瀏覽器視窗各自持有身分（不使用 Cookie）；同一視窗連續登入失敗會被暫時鎖定。
- 新增老師專屬操作的權限檢查：學生或未登入者呼叫一律回應無權限。
- 新增伺服器執行環境規範：所有參數可設定、只監聽 127.0.0.1、拒絕非本機 Host、以單一程序執行。
- 新增錯誤與機敏資料處理：所有訊息為繁體中文、不顯示堆疊與內部細節、密碼／Token／組別代碼不得出現在 log 與 repo，提供只含佔位值的 `.env.example`。
- 新增學習單匯入：上傳 Google Sheets 下載的 .xlsx，依表頭標籤動態解析題目列、填空格、合併儲存格與題組，先顯示確認畫面，老師確認後才保存；任何錯誤都整份拒絕並以繁中指出位置。
- 新增答案寫回：依一場已結束活動的伺服器判定結果，把成功答案寫入原學習單的填空格，產生新的 .xlsx，其他內容一律不變；寫回前驗證學習單結構與匯入時一致。
- 新增 CSV 結果匯出：5 欄、UTF-8 含 BOM、依題號與順位排序、題組依子題展開。
- 定義「活動最終結果」（ActivityResult）資料契約：本 change 的寫回與匯出只讀取此契約，由第二個 change 負責產生；在第二個 change 完成前，以測試用的結果資料驗證。

## Capabilities

### New Capabilities

- `teacher-auth`: 老師以密碼登入、每個視窗獨立的身分 Token、登入失敗鎖定、登出，以及老師專屬操作的權限檢查。
- `server-runtime`: 伺服器啟動條件、可設定參數、只監聽本機與 Host 檢查、單一程序執行。
- `error-and-secret-handling`: 繁中錯誤回應格式、不洩漏內部細節，以及密碼、Token、組別代碼在 log、程式碼與 repo 中的保護規則。
- `worksheet-import`: 上傳 .xlsx、動態解析學習單結構（表頭、題目列、填空格、題組）、匯入確認與取消、錯誤拒絕規則，以及已確認學習單的保存。
- `answer-writeback`: 把已結束活動的成功答案寫回原學習單填空格並產生新的 .xlsx，含結構一致性驗證與不改動其他內容的保證。
- `result-csv-export`: 已結束活動結果的 CSV 匯出格式、排序、題組展開與特殊字元處理。

### Modified Capabilities

（無，專案目前沒有既有 spec。）

## Impact

- 新專案骨架：Python 3.12、FastAPI、openpyxl（解析）、lxml（寫回時修改工作表 XML）、SQLite、伺服器提供的靜態 HTML + 原生 JavaScript、pytest。
- 新增 HTTP API：視窗註冊、老師登入／登出、學習單預覽／確認／取消／列表、活動寫回、活動 CSV 匯出。
- 新增資料目錄：SQLite 資料庫與已確認學習單的原始檔案（原檔永不修改）。
- 新增 `.env.example` 與 `.gitignore`（含 `.env` 與資料目錄）。
- 對第二個 change 的介面：ActivityResult 契約與「最終結果來源」介面；第二個 change 必須依此契約提供已結束活動的結果，並沿用本 change 的視窗身分、權限、錯誤格式與設定機制。
- 寫回與匯出的 API 在本 change 中已存在，但在第二個 change 完成前沒有任何已結束活動可供操作（呼叫會回應找不到活動）。
