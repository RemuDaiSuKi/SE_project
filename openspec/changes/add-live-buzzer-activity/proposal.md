# Proposal

## Why

前兩個 change 完成了老師登入、從 Google 試算表匯入學習單、答案寫回與 CSV 匯出，但系統還沒有搶答活動本身：結果來源 `NoActivitiesSource` 對任何活動都回答「找不到活動」，寫回與匯出因此沒有真正的資料可用。

本 change 加入線上分組搶答：老師用已確認的學習單建立活動並發組別代碼，學生用代碼加入組別、即時搶答，老師監看、判定無效，結束後保存結果，交給既有的寫回與 CSV 匯出。

期末要求兩組的基本功能一致。SpecKit 組已完成並驗證他們的 002（`silverwind63/SEFinal`），所以本 change 的操作結果以對方的**程式**為準。環境變數前綴、API 路徑、JSON 欄位命名與錯誤訊息用字維持本組的寫法。

## What Changes

- **活動與階段：** 老師用已確認的學習單建立活動，輸入 1–20 個組名，可覆寫冷卻設定。同一時間只能有一場準備中或搶答中的活動。階段只能依序前進：準備中 → 搶答中 → 已結束，沒有取消。伺服器重啟時，未結束的活動改為「已中斷」。
- **組別代碼：** 每組一個 6 碼代碼，字元集 32 個字（排除 0、1、I、O）。資料庫只存 SHA-256，明文只在記憶體。學生輸入代碼加入組別，代碼先去空白、轉大寫：
  - 格式錯誤不算失敗次數。
  - 每個視窗連續失敗 5 次鎖定 60 秒，另有全體每分鐘 60 次失敗的上限。
  - 代碼只能加入目前進行中的活動。
  - 老師可重新產生某組代碼，舊 Token 立即失效、該組的 WebSocket 被關閉。
- **送出與判定：** 學生以搶答單位（單題 `Q<n>`、題組 `G<n>`）送出。伺服器依固定順序檢查，任何一步失敗都不留紀錄、不佔順位。順位依伺服器處理順序，單位目前沒有成功者時就是成功。請求有多餘欄位時直接拒絕。
- **冷卻：** 即時送出成功後，若「該組成功數 − 全體最少成功數 ≥ K」，冷卻 N 秒（預設 K=2、N=10）。
- **判定無效：** 老師以單位為對象，把它目前的成功者判為無效，由順位最小的「未搶到」遞補。沒人可遞補時：搶答中單位重新開放，已結束則為無人搶答。通知只送給相關組別。
- **檢視與隔離：** 學生只看到本組資料，結束後另外看到每個單位的成功組與成功答案；老師看到全部。
- **即時同步：** 使用 WebSocket `/ws`。連線後第一則訊息帶 Token，先收完整快照，再收依身分過濾的增量事件。
- **保存：** 結束時在鎖內把全部送出寫進 SQLite，寫入成功才改階段。已結束活動重啟後可檢視、判定無效、寫回、匯出 CSV。以 SQLite 為後端的結果來源取代 `NoActivitiesSource`。
- **頁面：** 學生頁改為輸入代碼並進入組別畫面；老師頁加入建立活動、代碼、階段、即時監看、判定無效、結果、寫回與 CSV 下載。

## Capabilities

### New Capabilities

- `activity-lifecycle`: 建立活動、組別設定、單場限制、階段單向前進、重啟後標為已中斷。
- `group-access`: 組別代碼的產生與保存、加入、輸錯限制、重新產生代碼、學生身分。
- `buzzer-submission`: 搶答單位與標示、送出驗證順序、順位與成功判定。
- `fairness-cooldown`: 冷卻公式、設定、到期與活動結束時的處理。
- `success-invalidation`: 以單位判定無效、遞補、重新開放、通知。
- `result-visibility`: 學生與老師可見的範圍、結果 API、公開的階段查詢。
- `realtime-sync`: WebSocket 驗證、快照、依身分推播、撤銷連線。
- `result-persistence`: 結束保存、保存失敗處理、已結束活動的載入，以及提供給寫回與 CSV 的結果來源。

### Modified Capabilities

- `teacher-auth`: 「老師專屬操作」加入查看活動清單與活動監看。
- `server-runtime`: 「參數可設定」加入組數、組名長度、答案長度、冷卻、全體輸錯上限與 WebSocket 驗證逾時。

## Impact

- **新增模組：** `app/activity/`，包含純邏輯的判定引擎、代碼、搶答單位、registry 與 SQLite repository。另有 `app/api/activities.py`、`app/api/student.py`、`app/realtime.py`。
- **修改模組：**
  - `app/main.py`：註冊 router 與 WebSocket，啟動時標記已中斷，預設結果來源改為 SQLite。
  - `app/state.py`：加入 `require_group`。
  - `app/config.py`、`app/db.py`：schema 第 4 版只新增資料表。
  - `.env.example`、`README.md`。
- **新增 HTTP API：**
  - 活動：建立、列表、檢視、開始、結束、重新產生代碼、判定無效、結果、階段。
  - 學生：加入組別、送出、本組檢視。
  - WebSocket `/ws`。
- **前端：** 修改 `index.html`、`teacher.html`、`teacher.js`、`app.css`，新增 `student.js`。
- **既有的寫回與 CSV 端點不變。** 它們改從新的結果來源讀取已結束活動。
- **設計圖：** 更新 `component.puml`、`class.puml`，新增加入、送出、判定無效、結束保存的時序圖，以及活動狀態圖。
