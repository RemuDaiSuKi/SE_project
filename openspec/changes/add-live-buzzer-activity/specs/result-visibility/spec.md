# Spec Delta

## Purpose

規定學生與老師在活動各階段能看到哪些資料，確保結束前各組看不到他組的送出與單位狀態。

## ADDED Requirements

### Requirement: 學生的本組畫面
學生 SHALL 只看到以下資料：
- 階段、本組組名、本組的冷卻剩餘秒數
- 搶答單位清單（鍵值、標示、題號），MUST NOT 含任何單位狀態
- 本組的所有送出：單位、順位、結果（成功、未搶到、無效）與答案

活動結束後，學生 SHALL 另外看到完整結果：
- 每個單位的成功組與成功答案
- 各組成功數

學生 MUST NOT 看到他組未成功的答案。

#### Scenario: 結束前看不到他組
- **WHEN** 搶答中 B 組搶走了第 5 題
- **THEN** A 組的 API 回應與推播中，完全沒有第 5 題的狀態或 B 組的送出

#### Scenario: 結束後的結果
- **WHEN** 活動結束
- **THEN** 學生看到每個單位的成功組與成功答案、各組成功數，以及本組的全部紀錄（含被判無效的紀錄），看不到他組未成功的答案

#### Scenario: 中途加入的視窗
- **WHEN** 搶答中有新視窗加入 A 組
- **THEN** 新視窗立即看到 A 組既有的送出與結果

### Requirement: 老師的監看畫面
老師 SHALL 看到：
- 每個單位的狀態與全部送出（組別、答案、順位、結果）
- 各組的成功數與冷卻剩餘秒數
- 準備中與搶答中時，各組的代碼

單位狀態 SHALL 為下列之一：
- 尚無人搶答：沒有任何送出
- 已搶答：有成功者
- 重新開放：搶答中、有送出但沒有成功者
- 無人搶答：已結束且沒有成功者

#### Scenario: 監看送出
- **WHEN** 搶答中任何一組送出
- **THEN** 老師畫面顯示這筆送出的組別、答案、順位與是否成功，並更新成功數與冷卻狀態

### Requirement: 結果 API
活動結果 SHALL 只在活動結束後提供，未結束時回應「活動尚未結束，結束後才能檢視結果」：
- 老師：看到全部送出。
- 屬於該活動的學生：只看到每個單位的成功者與各組成功數。
- 其他請求：回應「無權限執行此操作」。

#### Scenario: 學生在結束前呼叫
- **WHEN** 搶答中學生呼叫結果 API
- **THEN** 系統回應「活動尚未結束，結束後才能檢視結果」

#### Scenario: 其他活動的學生
- **WHEN** 屬於上一場活動的學生 Token 呼叫這一場的結果 API
- **THEN** 系統回應「無權限執行此操作」

### Requirement: 公開的階段查詢
系統 SHALL 提供不需要 Token 的階段查詢，只回傳活動的階段，讓重啟後失去身分的學生視窗判斷活動是否已中斷。

#### Scenario: 重啟後判斷
- **WHEN** 搶答中伺服器重啟，學生視窗發現 Token 失效後查詢原活動的階段
- **THEN** 回傳「已中斷」，畫面顯示「活動已中斷，請老師重新建立」
